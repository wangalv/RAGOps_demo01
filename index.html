Top-K
How many results we return
K is simply how many passages the system hands back to you (or passes to the next stage). K=5 means the system picks its 5 best candidates. K=10 means it picks 10.

Bigger K = more chances to include the right answer, but more noise to sift through.
Recall@K  (R@K)
Did the answer make it into the results at all?
For each question we know the correct Act passage. Recall@K asks: is that passage anywhere in the top K?

One point if yes, zero if no — averaged across all 79 queries.

Think of it as: "What fraction of users would find the answer if they read all K results?"
Precision@K  (P@K)
How much of what we returned is actually useful?
Of the K results returned, how many are genuinely relevant? Precision@5 = 0.20 means on average only 1 of the 5 results is correct — the rest are noise.

Think of it as: "What fraction of the returned results are worth reading?"

Recall@5 = 1.0 — the correct answer IS in the top 5 → this query counts as a hit
Precision@5 = 0.20 — only 1 of 5 results is correct (1 ÷ 5 = 0.20)
Why Recall is the main goal here: This system feeds results into a second AI that reads them and generates an answer. If the correct answer never appears in the results at all, no downstream step can recover it. Getting the answer into the top-K pool (Recall) is therefore the critical hurdle — Precision matters secondarily.

Why R@5 < R@10 < R@20: A bigger pool has more chances to contain the right answer. R@5=0.75 vs R@20=0.878 does not mean the 20-result system is "smarter" — it just returns 4× more results, giving the correct answer more chances to sneak in.
